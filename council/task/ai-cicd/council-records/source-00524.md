## Recommended converged direction

1. **Choice and coverage.** Preserve the frozen Deployer answer “Your choice.” Prepare one identical-arm, pre-T0 frozen adapter with profiles for standalone GCE VM, Cloud Run, and their union. A static frontend, load balancer, CDN or DNS is path evidence, not restartable compute. Managed database/storage is recorded and not restarted. MIG, GKE, App Engine and other compute remain unregistered until a concrete profile is genuinely validated, independently reviewed and frozen before T0. A lawful but unsupported deployment yields `A5=UNVERIFIED` with an adapter-coverage reason, never a Deployer deployment-failure label. This is an instrument limit that must be visible in comparison reporting.
2. **Complete serving set.** Start from an authoritative provider inventory of the project's compute resources and classify every unit as serving compute, managed data, non-compute path, unrelated, or unclassified. Prove serving status through ingress/A2 route evidence **or** application dependency evidence for workers, private services and self-managed database VMs. Restart exactly every serving compute unit, not every running unit. A self-managed database VM is a VM serving the app; a provider-managed database is storage. Any unclassified compute unit blocks A5 verification. A known-present control must show that the inventory instrument detects resources.
3. **VM and managed actions.** Apply Master 02 §6.4 unchanged. Every serving VM must stop/start or reset; container or process restart alone fails. Cloud Run must prove replacement of every serving instance through provider-authoritative disjoint before/after identities or an equivalent proven zero-serving interval, plus old traffic/tag drainage, new serving revision, recovery and pre-action rationale. A new revision and 100% traffic alone are insufficient. Freeze **one** validated Cloud Run mechanism and its exact evidence rules before T0; Council's proposed CLI flags and logging fields remain unverified proposals.
4. **A5 outcome and storage.** The frozen A5 behavior remains the unique UI-created object's survival after a qualifying restart. Record provider disk/datastore identity and application-to-data binding where evidence can establish them; root filesystem UUID alone does not prove the database data path. Do not log database URL values, passwords or other credentials. A material contradiction between storage/binding and the object result leaves A5 unverified pending resolution. A missing optional classification is disclosed as a data-path evidence limit; it does not silently create a new A5 failure rule. A proposed stricter PASS prerequisite requires its own formal contract decision.
5. **Producer custody.** RW-6–RW-9 require exact executable/argv and exclusive stdout/stderr binding, with echo/comment/quote/redirection/unrelated-producer negatives. Concrete GCP commands, SDK version, JSON field paths, statuses and schemas come from genuine raw output, not Council guesses. Hash raw output, command logs and manifests. Preserve the Lima positive and R4 process/storage negatives.
6. **Review and ratification.** A fresh independent cross-model-family Executor Reviewer, selected in a later dispatch, reviews raw captures before narratives, all positive and adversarial cases, and the exact R5 hashes. Do not reserve the stopped Reviewer Actor 02 session by name. Human Operator ratifies the exact Record into the Addendum only after an unqualified review and completed authorized validation. Only then can WF-8 item 1 close; other WF-8 conditions remain separately open.

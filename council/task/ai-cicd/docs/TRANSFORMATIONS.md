# Transformation rules

Human Operator / Chair, Council Member A/B/C, Operations Coordinator and distinct role/actor IDs replace private names. Council seat labels never establish an actual model version. Qualified Executor, Reviewer, Observer, Deployer, auxiliary auditor and HTML implementation roles stay distinct. Session, resource, account, workspace, URL and private-reference placeholders preserve their documented relationships without publishing the reverse map.

Real private hostnames, domains, addresses, cloud/billing/account identifiers, credentials, local home paths, native client IDs and private source hashes are removed. Exact approved public project links may remain; the account handle in the workbench URL is not permission to print it elsewhere. Generic public upstream and official technical documentation links may remain when they contain no private identity or resource. Meaningful loopback/example addresses and public DNS resolvers (1.1.1.1 and 8.8.8.8) are distinguished from real deployment addresses. Explicit section/version citations are not IP addresses.

One canonical body is published per source. Byte-identical source files reuse that body. Native repeated prefixes reference canonical events; changed capture payloads remain variants. Close-increment equality is established after removing only export ordinal. Repeated client wrappers do not become additional conversations. Private images have actual-inspection textual derivatives and explicit original-image omissions. Missing attachments, unavailable citations, truncation, timeouts and refusals remain visible; no tail or conclusion is reconstructed.

Machine-readable fields and code remain readable historical data. Where a private string or a Chinese machine label requires replacement, the private alignment/report records that derivative. Public JSON is checked for parseability. Historical executable text is never run as a consequence of this archive. Records are neither normalized into emails nor rewritten into a success narrative.

Archive repair notes: a personal-name component in historical artifact/status identifiers uses the filename-safe OWNER_ stem; project coordination uses OPERATIONS_COORDINATOR_. A historical private operations root uses <OPERATIONS_ROOT>; these locators are redacted record text, not runnable public filesystem paths. A private literal scan target is labeled as such rather than replaced with the human's display role. Numeric cloud IDs use stable NUMERIC_RESOURCE aliases; a JSON numeric resource ID becomes an explicitly quoted alias string while other numeric measurements keep their values. Exact public upstream commit pins and original malformed commands/fatal outputs remain as captured. Approved public URLs are exact context exceptions, never permission for a bare account handle.
